A person's own AI agent uses Cover: a trip, a tight budget, and a red-team agent

Three Sonnet agents on the live server (localhost:8800, PayPal sandbox), each with only an agent token and /llms.txt. Maya's agent insures a Tokyo trip for two under $150 and simulates a late flight; Leo's agent works under a $30 limit with no autopay; Rin's agent is a security tester checking Cover's guardrails.

What happened

Every guardrail held: an already-delayed flight was refused (TR-3.1), the agent couldn't raise its limit or change where money goes, an over-limit purchase was refused, the injected claim stalled for evidence, and others' ids were refused. Rin's trip paid $100 by PayPal Payouts about a second after AM410 was reported 2.5 hours late. Maya's agent stopped rather than overspend: medical cover costs more than her $150.

What we fixed after

  • insure_trip no longer needs the oldest traveler's age for flight-only cover, and accepts its arguments wrapped as { answers } too
  • Flights may name their airports (from, to); otherwise they are still drawn from the flight number
  • A claim type the policy's plan doesn't include is refused up front with its clause, and flight claims say they are automatic
  • Trip premiums now count toward the person's monthly spending limit, and the limit message says so
  • The product list in errors includes travel; /llms.txt documents the demo controls as demo-only
